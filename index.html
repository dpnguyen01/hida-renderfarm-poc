2 · What $200 buys on AWS Deadline Cloud

Your bill = three stacked components, charged per worker-hour while a fleet is running (scales to zero = $0):

1. EC2 compute The instance itself. Spot is far cheaper than On-Demand; "Wait & Save" is cheaper still for non-urgent jobs. A small Linux worker ≈ $0.20–0.50/hr spot; a big GPU worker can be $3–8+/hr.
2. Deadline Cloud mgmt fee AWS's charge to run the farm, per worker-hour, scaled to instance size. (CMF reference point: ~$1/worker-hr. SMF varies by instance.)
3. Usage-based licensing (UBL) Only if you use managed Maya/Arnold/Nuke/etc. licenses — billed per hour per product while rendering. This is the sneaky one: Maya + Arnold together can add $1–3+/hr on top. Bring-your-own-license avoids it.

Rough blended rate per worker-hour (small Linux spot + mgmt + light UBL): ballpark $1–2/hr. Heavy GPU + Maya/Arnold UBL: easily $6–12/hr.

So what does $200 get?
  • ~100–200 worker-hours at the light end (small CPU jobs, BYO or no license).
  • ~15–30 worker-hours at the heavy end (GPU + managed Maya/Arnold).

Translated to "jobs": a worker-hour is one instance running for an hour, and a job fans out across many workers in parallel. So a single 240-frame animation at ~2 min/frame on 10 workers ≈ 8 worker-hours ≈ $8–16 light / $50–100 heavy.

Realistic POC envelope: comfortably 5–15 small-to-medium real render jobs, OR 1–3 heavy GPU/animation jobs, with budget headroom to iterate. Enough to prove it end-to-end and get a true cost-per-frame for HIDA's actual scenes. Not enough for a class — a 30-student course would blow $200 in days.

Exact SMF per-instance mgmt fee lives in a dynamic pricing table I couldn't scrape — these are grounded order-of-magnitude figures from AWS's published cost model (3 components, CMF ~$1/worker-hr reference, UBL per-product-per-hour). Pin exact numbers via the AWS Pricing Calculator once we know HIDA's DCC + renderer + instance type.
